# backup_v4.sh

Третья вариация скрипта резервного копирования. Написана в
функциональном стиле: вся логика разбита на небольшие функции
(`check_args`, `check_source_dir`, `ensure_dest_dir`,
`make_archive_path`, `create_archive`), а точка входа — функция
`main()` в самом конце файла.

## Использование

```bash
chmod +x backup_v4.sh
./backup_v4.sh <откуда> [<куда>]
```

- **`<откуда>`** — директория-источник (обязательный аргумент).
- **`<куда>`** — директория для сохранения архива (необязательный
  аргумент, по умолчанию `/backup`).

## Примеры

```bash
./backup_v4.sh /var/www/site /mnt/backups
./backup_v4.sh /var/www/site
```

## Формат имени архива

```
<имя_папки>__<ГГГГ_ММ_ДД-ЧЧММ>.tar.gz
```

Например: `site__2026_09_14-1732.tar.gz`

## Структура скрипта

| Функция              | Что делает                                              |
|----------------------|----------------------------------------------------------|
| `print_error` / `print_info` | Единый формат вывода сообщений (`[!]` и `[i]`) |
| `check_args`         | Проверяет, что передан хотя бы один аргумент             |
| `check_source_dir`   | Проверяет существование директории-источника             |
| `ensure_dest_dir`    | Создаёт директорию назначения при необходимости, проверяет права на запись |
| `make_archive_path`  | Формирует итоговый путь к архиву с датой в имени          |
| `create_archive`     | Запускает `tar` и обрабатывает результат                  |
| `main`               | Связывает все шаги вместе, точка входа скрипта             |

## Проверки и обработка ошибок

Каждая функция-проверка возвращает код `0` (успех) или `1` (ошибка) и
сама печатает понятное сообщение через `print_error`. Если любая из
проверок не проходит, `main()` завершает скрипт с кодом `1`. При сбое
архивации недописанный `.tar.gz`-файл удаляется.

## Требования

- Bash
- Утилиты `tar`, `date`, `mkdir`, `basename`, `dirname`

## Чем отличается от остальных вариаций

Функционально — ничем, но код разложен на отдельные функции, что
удобно, если скрипт нужно будет расширять (например, добавить
логирование или новые проверки) — не трогая остальную логику.
